# Music Genre Classification

Проект по классификации музыкальных треков по жанрам на основе их аудиохарактеристик.

Цель проекта — исследовать, насколько хорошо классические методы машинного обучения способны определять музыкальный жанр по числовым аудиопризнакам, сравнить разные модели и проанализировать причины ошибок классификации.

Задача:

Необходимо определить жанр музыкального трека по набору его аудиохарактеристик.

Это задача многоклассовой классификации: в исходном датасете представлено 114 жанров, однако после фильтрации данных для моделирования осталось 112 жанров.

В качестве признаков используются только аудиохарактеристики трека. Метаданные о названии трека, исполнителе и альбоме в финальную модель не включались.

Данные:

В работе использован Spotify-подобный датасет с информацией о музыкальных треках.

Исходный датасет:

* 114 000 записей;
* 21 признак;
* 114 жанров;
* около 89 700 уникальных `track_id`.

После очистки и подготовки данных для моделирования использовались следующие аудиопризнаки:

* `danceability` — танцевальность;
* `energy` — энергетичность;
* `key` — тональность;
* `loudness` — громкость;
* `mode` — лад;
* `speechiness` — доля речевых фрагментов;
* `acousticness` — акустичность;
* `instrumentalness` — вероятность инструментального трека;
* `liveness` — вероятность присутствия живого исполнения;
* `valence` — музыкальная позитивность;
* `tempo` — темп;
* `time_signature` — размер.

Итоговая матрица признаков для моделирования содержит 12 признаков.

Основная часть исследования представлена в Jupyter Notebook: от разведочного анализа и очистки данных до обучения моделей и анализа ошибок.

Этапы работы:

1. Разведочный анализ данных

На первом этапе были исследованы:

* размер и структура датасета;
* пропущенные значения;
* количество уникальных треков;
* распределение жанров;
* дубликаты;
* распределение аудиопризнаков;
* корреляции между признаками;
* выбросы.

После очистки данные были подготовлены для дальнейшего моделирования.

2. Анализ распределения жанров

Количество объектов в разных жанрах существенно отличается.

Для отдельного анализа была сформирована выборка с уникальными сочетаниями трека и жанра. В ней:

* 73 789 записей;
* 73 441 уникальный трек;
* 112 жанров.

Наиболее малочисленным классом оказался `reggaeton` — 72 записи, наиболее многочисленные классы содержали около 1 000 записей.

Это важно учитывать при оценке модели: одной только Accuracy недостаточно, поскольку качество классификации может сильно различаться между жанрами.

3. Анализ корреляций

Наиболее заметные зависимости между признаками:

| Признаки                    | Корреляция |
| --------------------------- | ---------: |
| `energy` — `loudness`       |      0.757 |
| `energy` — `acousticness`   |     -0.731 |
| `loudness` — `acousticness` |     -0.578 |

Также был рассчитан VIF для оценки мультиколлинеарности.

Несмотря на заметную корреляцию между `energy` и `loudness`, последующий эксперимент с удалением признаков показал, что оба признака полезны для классификации, поэтому они были сохранены в финальной модели.

Модели:

В проекте были рассмотрены два подхода.

### Logistic Regression

Логистическая регрессия использовалась как базовая модель.

Перед обучением признаки были стандартизированы с помощью `StandardScaler`.

Результаты на validation:

| Metric      |  Score |
| ----------- | -----: |
| Accuracy    | 0.2104 |
| Macro-F1    | 0.1361 |
| Weighted-F1 | 0.1759 |

XGBoost

В качестве основной модели использовался `XGBClassifier`.

Параметры финальной модели:

```python
XGBClassifier(
    n_estimators=300,
    max_depth=8,
    learning_rate=0.08,
    subsample=0.8,
    colsample_bytree=0.8,
    objective="multi:softprob",
    eval_metric="mlogloss",
    tree_method="hist",
    random_state=42,
    n_jobs=-1
)
```

Данные разделялись с использованием стратификации:

* train — 59 031 объект;
* test — 14 758 объектов.

Результаты:

Финальная модель XGBoost показала следующие результаты на тестовой выборке:

| Model               |   Accuracy |   Macro-F1 | Weighted-F1 |
| ------------------- | ---------: | ---------: | ----------: |
| Logistic Regression |     0.2104 |     0.1361 |      0.1759 |
| XGBoost             | **0.3415** | **0.3132** |  **0.3332** |

XGBoost заметно лучше справился с задачей классификации по всем трём рассматриваемым метрикам.

### Почему используются три метрики

**Accuracy** показывает долю правильных предсказаний среди всех объектов.

**Macro-F1** рассчитывает F1 отдельно для каждого класса и затем усредняет результаты. Эта метрика особенно важна при наличии различий в количестве объектов разных жанров.

**Weighted-F1** также усредняет F1 по классам, но учитывает размер каждого класса.

Разница между Accuracy и Macro-F1 показывает, что качество классификации неоднородно между жанрами.

## Анализ важности признаков

Для XGBoost была рассчитана важность признаков.

Наиболее значимыми оказались:

| `energy`           |     0.0845 |

| `loudness`         |     0.0815 |
| `tempo`            |     0.0800 |
| `speechiness`      |     0.0796 |
| `time_signature`   |     0.0759 |
| `liveness`         |     0.0626 |
| `key`              |     0.0538 |

Важности распределены достаточно равномерно: модель использует все 12 признаков, поэтому исключение отдельных признаков только на основании их относительной важности не выглядит оправданным.

Feature Ablation

Дополнительно было проверено влияние коррелированных признаков `energy` и `loudness`.

| Набор признаков           |   Accuracy |   Macro-F1 | Weighted-F1 |
| ------------------------- | ---------: | ---------: | ----------: |
| Все признаки              | **0.3415** | **0.3132** |  **0.3332** |
| Без `loudness`            |     0.3258 |     0.3003 |      0.3180 |
| Без `energy`              |     0.3258 |     0.3008 |      0.3179 |
| Без `energy` и `loudness` |     0.3028 |     0.2788 |      0.2943 |

Эксперимент показывает, что высокая корреляция между признаками не означает, что один из них можно без потери качества удалить.

При удалении обоих признаков Accuracy снизилась с 0.3415 до 0.3028, а Macro-F1 — с 0.3132 до 0.2788.

Поэтому в финальной модели `energy` и `loudness` сохранены.

Анализ ошибок:

Помимо общих метрик, были исследованы ошибки классификации по отдельным жанрам и наиболее частые пары перепутанных классов.

Наиболее характерные случаи:

```text
chicago-house  → detroit-techno
detroit-techno → chicago-house

death-metal → grindcore
grindcore   → black-metal

samba → pagode
gospel → world-music

minimal-techno → detroit-techno
punk-rock      → power-pop
```

Например:

* `chicago-house → detroit-techno`: 35 ошибок;
* `detroit-techno → chicago-house`: 33 ошибки;
* `death-metal → grindcore`: 24 ошибки;
* `samba → pagode`: 25 ошибок;
* `minimal-techno → detroit-techno`: 26 ошибок.

Для некоторых жанров ошибка особенно заметна относительно размера класса. Например, для `techno` 20 из 78 объектов были классифицированы как `minimal-techno`, что соответствует ошибке около 25.6%.

Что показывает анализ:

Модель способна извлекать полезный сигнал из аудиохарактеристик: итоговая Accuracy составляет 0.3415, тогда как случайный выбор одного из 114 исходных классов дал бы вероятность правильного ответа около 0.9%.

При этом качество сильно зависит от жанра.

Модель относительно хорошо распознаёт некоторые характерные классы, но испытывает сложности при разделении близких жанров и поджанров.

Это закономерно для используемого набора признаков: числовые аудиохарактеристики хорошо описывают общие свойства звучания, но не содержат всей информации, которая может быть необходима для различения близких музыкальных жанров.

## Ограничения

Основное ограничение проекта — использование только агрегированных аудиохарактеристик.

В модели не используются:

* текст песни;
* информация об исполнителе;
* название и контекст трека;
* последовательность аудиосигнала;
* спектральные представления;
* аудиоэмбеддинги.

Поэтому дальнейшее улучшение качества можно исследовать через более информативное представление самого аудио и добавление дополнительных источников информации.
